# ADR-0004: pinned content consumption before task creation

Status: Accepted for P4 implementation; independent exact-candidate review remains external.

The PO must compare rich source requirements against actual implementation
assertions and executed results. Names, an index and summaries cannot provide
behavioral evidence. Repository content is untrusted and cannot define commands
or controller paths.

Pin each batch to a commit. Record complete section reads and attached images;
validate total anchor/image coverage. Commit provenance-bearing digests with
architecture before creating task workspaces. Treat AST inventory only as
discovery. Union selected files with mandatory linked tests/results, supply full
contents under per-requirement bounds and validate every evidence citation
against supplied content hashes. Merge chunk comparison rows before one global
0–6 task synthesis. Missing or unread evidence cannot support implemented status.

Keep native scheduling, schema classification and quota admission in the existing
engine/runner. Architecture additions require a fresh different-family strong
read-only review and a durable candidate before CAS. Protect digests from writers;
regenerate the documentation index before candidate snapshotting.

Consequences: conservative evidence gaps are visible; unavailable content blocks
rather than inventing proof. Exact provenance proves delivery of content, not
understanding. The independent P5 canary remains necessary for live reasoning,
pixels, actual provider profiles and the full native lifecycle.
