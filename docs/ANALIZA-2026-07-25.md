## A. Rekurencyjna amplifikacja kontekstu przez `.forge/logs` — błąd nr 1

### A.1 Co się dzieje

Tester nie dostaje w promptcie realnego handoffu (tylko string `reason` /
`summary`), więc **szuka kontekstu na dysku i czyta surowe logi poprzednich
agentów**:

```

                           .forge/logs/iter-0353-review.log .forge/logs/iter-0353-coder.log; do
                      sed -n '1,220p' "$f"; done
iter-0356-tester: for f in .forge/logs/iter-035{1,2,3,4,5,6}-*.log; do tail -n 100 "$f"; done
```

Te logi to JSONL, gdzie **jedna linia = jedno zdarzenie codeksa i potrafi mieć
1,26 MB**. `tail -n 100` to nie 100 linii tekstu, tylko megabajt. A ponieważ log
rundy N zawiera wyjścia narzędzi rundy N, runda N+1 wciąga je do siebie i
zapisuje do własnego logu.

Sprzężenie zwrotne widać wprost w rozmiarach logów testera:

```

iter-0346-tester      32 173 B
iter-0347-tester      57 999 B
iter-0348-tester     171 970 B
iter-0349-tester     310 322 B
iter-0353-tester   1 346 523 B   <- zapłon
iter-0354-tester   1 286 649 B   <- czyta log 0353
iter-0356-tester   1 272 564 B   <- czyta logi 0351-0356
```

Trzy pojedyncze wywołania narzędzi po ~1,03 MB każde. Łącznie **4,16 M znaków
(~1 M tokenów) wyjścia narzędzi u samego testera w godzinę**; stąd ~145 k
tokenów wejścia na jedno wywołanie testera. **To się samo nie zatrzyma** —
każda kolejna runda będzie ≥1 MB.

Zapłon (iter-0353):

```bash

find .forge -maxdepth 3 -type f           # 411 plików zadań

omija, a `codex_sandbox = danger-full-access` ([config.py:311](../forge/config.py#L311))

- [ ] **F-11 — Licznik rund bez zmian w plikach** *(H.1)*
  Deterministyczny, bez LLM i bez bramki: przy 2 kolejnych rundach z pustym

  blokuje. Jedyny mechanizm, który zauważy nawrót problemu A.
